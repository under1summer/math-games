# Перестрелка

Открыть: https://under1summer.github.io/math-games/perestrelka.html

## Проведение

1. Создайте игру, задайте 2–16 названий команд. По умолчанию 8 обойм, интервал 15 минут (120 минут игры).
2. В «Личные ссылки и табло» сохраните ссылку ведущего, раздайте командные ссылки и откройте общее табло на проекторе. Ссылка ведущего даёт управление: её не раздают командам. Последние игры запоминаются в этом браузере.
3. Раздайте условия отдельно. Нажмите «Начать игру». Онлайн команды отправляют ответы и выбирают цель выстрела. Задачи с ключами проверяются автоматически; ведущий проверяет остальные и может изменить вердикт. В режиме аудитории команды сдают листочки, ответы вносит ведущий.
4. Пауза останавливает таймер и приём ответов. Следующая обойма выдаётся автоматически, либо кнопкой ведущего. Старые обоймы доступны до конца.
5. Ошибочную сдачу можно отменить в журнале с причиной. Есть отмена последней сдачи/коррекции и ручная коррекция HP. После отмены результаты пересчитываются, а задача снова доступна.
6. По окончании побеждает команда с максимальным HP, при равенстве место делится. Журнал можно скачать JSON. «Новая игра» создаёт отдельную встречу со свежими ссылками, сохраняя старую.

## Восстановленные правила

Источник переноса: ранее согласованные «Перестрелка.pdf», README преподавателя и `perestrelka_new_formula.html`; позднейшие пожелания о 16 командах и вводе ответов только ведущим.

- У каждой команды 100 HP и меткость 50%. После каждой попытки меткость равна `(1 + число верных)/(2 + число всех попыток)`. Аптечки тоже учитываются.
- Верный выстрел попадает с меткостью **до** этой сдачи. Сервер выбирает случайное число от 0 до 1. Неверный ответ расходует попытку без выстрела.
- Урон: `max(3, HP стрелка / 5)`. Дробные значения сохраняются; HP цели не опускается ниже нуля.
- Одна попытка каждой команды на каждую задачу. В обойме 6 задач.
- 20 аптечек: по 4 на +2, +5, +10, +15 HP и по 2 на +20, +25. Верная добавляет HP, неверная расходуется. HP может превышать 100; команда с нулём HP продолжает играть.
- Автоматическая выдача обойм и завершение считаются по серверному времени. Обновление экранов каждые 6 секунд, отображение таймера каждую секунду.
- При отмене сохраняются случайные числа последующих выстрелов. Меткость и урон пересчитываются из оставшегося журнала, новые случайные числа не генерируются.

## Устройство и безопасность

`perestrelka-schema.sql` — первоначальная установка в существующем Supabase. Выполнять один раз. Все объекты имеют префикс `ps_`; таблицы и функции других игр не изменяются.

Таблицы `ps_games`, `ps_teams`, `ps_tasks`, `ps_events` закрыты RLS и запретом прямого доступа anon/authenticated. Единственная клиентская точка входа — `ps_api`. Право ведущего проверяется на сервере по SHA-256 случайного секрета. Командная ссылка даёт только чтение; общее табло открыто по идентификатору игры. В открытом состоянии нет секретов ведущего и токенов команд. Публичный publishable key не является правом ведущего.

Мутации сериализуются блокировкой игры. Сдача, коррекция и отмена имеют UUID запроса для защиты от повторной обработки одного запроса. Вердикт, выдача задач, доступность попытки, время и случайность проверяются на сервере. Пользовательские тексты экранируются.

Создание встреч открыто, как и у других игр платформы; квоты Supabase остаются общими. Автоматическая очистка архивов не реализована.

## Будущие расширения (не реализованы)

В снимках `ps_tasks` зарезервированы `bank_task_id`, `bank_version`, `kind`, `module_id`, `module_version`, `module_config`, `statement`. Банк сможет подставлять версионированное условие в снимок встречи. `renderTaskContent` является точкой подключения будущего отображения; неподдерживаемые модули не принимаются сервером. Общего банка, редактора и интерактивных модулей сейчас нет.

## Проверка

`perestrelka-tests.sql` запускается владельцем в SQL Editor, создаёт временные тестовые встречи и полностью откатывается. Проверяет формулы, попадание/промах, дробный и минимальный урон, нулевые HP, аптечки, единственную попытку, повтор запроса, отмены, паузу, выдачу обойм, дедлайн, архив, права и неизменность данных `od_*`/`ab_*`.

Интерфейс проверяется на опубликованной странице: создание, настройка, старт, вердикты, журнал, отмена, пауза, командная ссылка, компактное табло и завершение.

## Математическая биржа

В каталоге есть неактивная карточка. Полные согласованные правила и исходный код не найдены. Сохранившихся фрагментов о ценах задач недостаточно для восстановления инвестиций и начислений. Реализация, таблицы и начисления Биржи пока не создавались.

Общие возможности, Excel, режим аудитории и проверки: см. `PLATFORM_README.md`. Указание о вводе только ведущим относится к прежней версии; текущая поддерживает оба формата.
