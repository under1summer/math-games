# Математическая абака

Перенос ранее согласованной игры на GitHub Pages + Supabase. Google-сервисы и внешние JavaScript-зависимости не используются. Данные «Оптом дороже» не изменяются: у абаки отдельные таблицы и функции с префиксом `ab_`.

## Для ведущего

1. Откройте [абаку](https://under1summer.github.io/math-games/abaka.html) и создайте игру. Сохраните личную ссылку ведущего отдельно; её копия остаётся в текущем браузере.
2. Задайте 1–32 названия команд, 1–12 тем, 1–12 задач в теме и длительность 1–300 минут. По умолчанию — 3 команды, поле 5×5, 90 минут.
3. Сохраните настройки. В разделе «Условия и ключи ответов» заполните названия тем, условия, режимы проверки и ключи. Сохраните задачи. Настоящие условия/ключи вводятся здесь, в закрытой базе, а не в публичном репозитории.
4. Раздайте личные ссылки капитанам и нажмите «Начать игру». Условия и ключи фиксируются на старте. До старта участники не видят условия.
5. Проверяйте очередь ответов. Можно писать комментарии, исправлять вердикты и отменять сдачи. Фотографии видны в карточке проверки; в увеличенном окне тоже есть «Верно» и «Неверно».
6. Закройте приём ответов или дождитесь конца таймера. Проверка остаётся доступна. «Новая игра» создаёт отдельную копию условий/ключей и новые ссылки команд; прежняя игра полностью сохраняется.
7. «Скачать результаты» выгружает JSON с результатами, ключами и журналом. Экспорт предназначен только ведущему, не передавайте его командам. Фотографии остаются в закрытой базе и доступны из истории игры.

## Сохранённые правила

Все условия доступны после старта. Темы решаются параллельно; внутри темы ответы отправляются по порядку. Отправка предыдущей задачи открывает следующую, ждать вердикта не нужно. Одна попытка на задачу. Неполный/неверный ответ приносит 0, верный — `10 × номер задачи`.

Полностью верная тема даёт бонус `10 × количество задач в теме`; полностью верный столбец — `10 × номер столбца`. Первый завершивший каждую линию получает её бонус вдвойне. Время линии — максимальное время получения её верных ответов сервером, с точностью до миллисекунды. Проверка фото позже не изменяет это время. При совпадении времени первенство разделяется. Бонусы пересчитываются при исправлении оценок и отменах; до завершения ручных проверок они предварительные.

Места определяются общей суммой, затем суммой бонусов. При равенстве обоих показателей место общее.

Числа: точка/запятая, дроби вида `1/2`; без угадывания единиц и выражений. Набор чисел: разделитель `;`, порядок не важен, повторы важны. Альтернативы ключа разделяются `|`. Текст нормализуется по NFKC, регистру, ё/е и пробелам. Нераспознанные числа, неизвестный текст, режим «Вручную» и все картинки идут ведущему. Фото: JPG/PNG/WebP до 4 МБ. Отмена сохраняет запись в истории и разрешает повторную отправку; уже открытые более поздние задачи не удаляются.

## Устройство и безопасность

- `ab_games`: настройки, SHA-256 секрета ведущего, время, неизменяемый снимок задач на старте.
- `ab_teams`: участники и индивидуальные случайные секреты ссылок.
- `ab_tasks`: редактируемые условия, приватные ключи, зарезервированные ссылки расширений.
- `ab_submissions`: ответы, серверное время, оценка, комментарий; частичный уникальный индекс защищает единственную активную попытку.
- `ab_photos`: закрытые изображения с проверкой размера, MIME и заголовка файла.
- `ab_events`: журнал создания, настройки, старта, закрытия и изменений оценок.

RLS включён на всех таблицах, прямой доступ anon/authenticated отозван. Единственная публичная точка — `ab_api` с проверкой личной ссылки. Вспомогательные функции закрыты, `search_path` фиксирован. Публичное табло содержит суммы, бонусы и статусы клеток; тексты ответов, фото и ключи доступны лишь ведущему или своей команде (ключи — только ведущему). Секреты ссылок находятся во фрагменте URL, не отправляются GitHub и не публикуются в коде. Publishable key предназначен для публичного клиента; service_role не используется.

Ответы, права доступа, порядок и таймер проверяет сервер. Запись и оценивание сериализуются блокировкой строки игры. UUID запроса обеспечивает безопасный повтор при сбое; неподтверждённая попытка сохраняется локально. Фото читается сразу при выборе, чтобы ошибка чтения была видна до отправки. Табло обновляется примерно каждые 12–15 секунд. Таймер корректируется по серверным часам.

Создание новых игр работает без регистрации; ссылку ведущего необходимо сохранить самостоятельно. При её потере восстановление возможно только администратором БД. Не передавайте детям ссылки ведущего и экспорт с ключами.

## Подключение будущих расширений — только контракт

Банк задач и интерактивные модули **пока не реализованы**. Для последующего подключения предусмотрены:

| Поле / точка | Назначение |
| --- | --- |
| `bank_task_id`, `bank_version` | Ссылка на общую задачу и выбранную версию; будущий импорт копирует содержимое в игру. |
| `kind` | Тип содержимого; сейчас поддерживается только `standard`. |
| `module_id`, `module_version`, `module_config` | Версия интерактивного отображения и его публичные параметры. Сейчас пустые. |
| `frozen_tasks` | Снимок содержимого, источника, версии и ключа на старте: изменения банка не должны менять начатую игру. |
| `renderTaskContent(container, task)` | Единственная точка отображения условия; позже здесь подключается нужный модуль. |
| `ab_api('submit', ...)` | Проверка попытки, прав, порядка, дедлайна и начисление баллов остаются на сервере независимо от будущего типа задачи. |

Новые поля сохраняются при редактировании и копировании игры. Произвольный код из БД не исполняется. Текущий сервер отклоняет неподключённые типы модулей; банк не имеет таблиц, интерфейса или фиктивных функций. Будущему интерактивному типу потребуется отдельная серверная валидация структурированного ответа, без клиентского назначения вердикта.

## Установка и проверка

`abaka-schema.sql` выполняется один раз в существующем проекте Supabase. Затем публикуются `abaka.html` и обновлённый `index.html` через GitHub Pages. Миграция только добавляет `ab_*`; изменения `od_*` отсутствуют.

`abaka-tests.sql` проверяет парсеры, права, скрытие ключей, порядок, единственную попытку, повтор запроса, картинки, расчёт баллов/бонусов, ничьи, отмену, архив, серверный дедлайн и неизменность данных «Оптом дороже». Все фикстуры откатываются транзакцией.
