# Единый модуль задач и вложений

Общий редактор работает в настройках ведущего. Он обслуживает Оптом дороже, Абаку, Перестрелку и подготовку задач Биржи. Проведение Биржи не реализовано: полных согласованных правил в проекте нет.

## Работа ведущего

1. Настройте команды и размеры поля, затем откройте раздел задач.
2. Выберите позицию. Введите условие и ключ либо импортируйте XLS/XLSX. Скачать шаблон и инструкцию можно там же; шаблон содержит текущие позиции игры и отдельный лист «Инструкция».
3. Формулы: `$...$`, `$$...$$`, `\(...\)`, `\[...\]`. HTML в условии не выполняется. KaTeX, SheetJS и HEIC-конвертер размещены в репозитории, обращения к Google нет.
4. Для разрезания выберите соответствующий тип, задайте сетку/части/требование, нарисуйте фигуру и проверьте связность. Откройте предпросмотр и попробуйте решение.
5. Нажмите **Сохранить задачи игры** до старта. Запуск фиксирует условия, ключи, интерактивную конфигурацию и правила вложений. Игровые баллы и очередность попыток остаются прежними.

### Банк

По умолчанию задача принадлежит только игре. Для постоянного банка войдите по почте/паролю Supabase Auth; при регистрации может потребоваться подтверждение письмом. Галочка **Сохранить в банк задач** включает отдельное сохранение. Банк личный для учётной записи и общий между играми. Другие преподаватели и ученики его не видят.

Поиск показывает до 100 совпадений. Выбор копирует конкретную версию в игру; дальнейшее редактирование банка эту копию не меняет. Дубликаты определяются по условию без различий регистра/лишних пробелов, типу и конфигурации. Повторное сохранение идентичной задачи возвращает существующую запись. Редактирование создаёт новую версию. Ручное удаление удаляет банк и версии, сохраняя независимые игровые копии. Изменение копии отвязывает её от версии банка, пока ведущий явно не сохранит её в банк.

### Вложения

В каждой задаче: запрещено / необязательно / обязательно. К одному ответу — до 6 файлов JPG, PNG, HEIC/HEIF, PDF, исходный размер каждого до 20 МБ. Есть отдельный выбор из галереи/файлов и съёмка камерой. Фото уменьшаются до 2000 px по длинной стороне с JPEG quality 0.82, когда это сокращает размер. PNG сохраняется, если JPEG оказался больше. HEIC конвертируется локально; если браузер и конвертер не распознали конкретный вариант HEIC, оригинал можно сохранить и скачать, но встроенное изображение может быть недоступно.

Перед отправкой есть просмотр и удаление. Разрешено прикладывать файлы к тексту/числу/разрезанию или отправлять только файлы. Для замены интерактивного решения файлами есть отдельная галочка. Чисто файловое решение поступает на ручную проверку. В Абаке файловые стандартные решения, как и прежние фотографии, проверяет ведущий; интерактивное решение проверяется сервером, если оно отправлено. Оптом дороже и Перестрелка сохраняют прежнюю автопроверку текстовых ключей. Требование файла проверяется и на сервере. При бумажном режиме ведущий может выставить оценку бумажному решению без загрузки файла.

В таблице проверки ведущий открывает файлы и скачивает их. Storage закрытый: доступа к спискам и объектам у anon/authenticated нет. Edge Function проверяет ссылку ведущего либо команды и её принадлежность игре. Подписанные ссылки действуют 60 секунд. JWT gateway остаётся включён. Сервисный ключ берётся только из окружения Supabase, в исходниках его нет. Старые фотографии в bytea/data URL продолжают открываться.

## Хранение

- Банк: до ручного удаления.
- Детали новой игры (условия, ответы, фото, файлы, разрезы): 7 дней после завершения.
- Итоговая таблица новой игры: 30 дней.
- Неактивный новый черновик: 30 дней.
- Неотправленные загрузки: 24 часа, чтобы не накапливать брошенные файлы.
- Игры, существовавшие до установки модуля, помечены `protected` и автоматически не удаляются.

`math-games-retention` запускается ежечасно на 17-й минуте, `math-games-file-retention` — на 27-й. Файлы удаляются через Storage API; SQL не удаляет строки `storage.objects` напрямую. Ошибки Storage оставляют очередь для следующего запуска. До очистки подробностей фиксируется итоговая таблица. Ведущий может скачать результаты XLSX и досрочно удалить завершённую игру с подтверждением.

## Установка на существующий проект

1. Сохраните резервную копию проекта. Примените `task-module.sql` **один раз** после прежних схем и platform-update.
2. Примените `attachments.sql` **один раз**. Она обновляет функции для поддержки вложений и добавляет закрытый bucket.
3. Разверните `game-files.ts` как Edge Function **game-files**, оставив **Verify JWT ON**. Supabase автоматически предоставляет `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`. Настройка исходника записана в `supabase-config.toml`.
4. Опубликуйте HTML/JS/CSS, локальные KaTeX-шрифты и библиотеки на GitHub Pages.
5. Выполните `task-module-tests.sql`, `attachments-tests.sql`, `platform-tests.sql`, `review-tests.sql`, `bank-copy-tests.sql`; тесты откатывают свои данные.

SQL-файлы установки не являются повторно запускаемыми миграциями. Не запускайте старый `platform-update.sql` поверх обновлённого модуля: он содержит более ранние определения API.

## Расширение

`TaskModules.register(id, {validate, mount, check})` — клиентский контракт модуля. Конфигурация и версия сохраняются в игровой копии. Сервер допускает только зарегистрированный реализованный тип; новый тип требует отдельного серверного валидатора/проверяющего. Ответ ученика не может передать готовый вердикт.
